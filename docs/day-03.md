# Day 3 – Automated Security Alerting with Amazon SNS

## Objective

Extend the BonTech Serverless Security Incident Automation platform by adding automated security notifications using Amazon SNS.

The goal is to ensure that after a security event is detected and processed, the security analyst receives an email notification containing the incident details.

## Architecture

IAM Security Activity
↓
AWS CloudTrail
↓
Amazon EventBridge
↓
AWS Lambda
↓
Amazon DynamoDB
↓
Amazon SNS
↓
Security Analyst Email

CloudWatch Logs provide operational visibility into the Lambda execution.

## Services Used

- AWS CloudTrail
- Amazon EventBridge
- AWS Lambda
- Python
- Boto3
- Amazon DynamoDB
- Amazon SNS
- Amazon CloudWatch
- AWS IAM

## Implementation

### 1. Created SNS Security Alert Topic

Created an Amazon SNS topic named:

`BonTech-Security-Alerts`

The topic acts as the notification channel for security incidents processed by the Lambda function.

### 2. Configured Email Subscription

An email subscription was created and confirmed for the SNS topic.

This allows security alerts generated by the automation system to be delivered directly to a security analyst.

### 3. Applied IAM Least Privilege

The Lambda execution role was extended with a dedicated policy:

`BonTech-Lambda-SNS-Publish-Policy`

The policy grants only the `sns:Publish` permission against the BonTech security alert topic.

This maintains the principle of least privilege.

### 4. Integrated SNS with Lambda

The Python Lambda function was updated to initialize an SNS client using Boto3.

After an incident is processed and stored in DynamoDB, Lambda publishes an alert containing:

- Incident ID
- Event Type
- Severity
- Status
- Source
- Description

### 5. Tested Automated Alerting

A controlled `AttachUserPolicy` security event was processed.

The Lambda function:

1. Received the security event.
2. Generated an incident ID.
3. Classified the incident as HIGH severity.
4. Stored the incident in DynamoDB.
5. Published the security alert to Amazon SNS.
6. Delivered the notification to the subscribed security analyst email.

## Validation

CloudWatch logs confirmed successful execution of the workflow.

The logs showed that:

- The security event was received.
- The incident was processed.
- The incident was successfully stored in DynamoDB.
- The SNS alert was successfully published.

DynamoDB also contained the generated incident record.

The subscribed email account successfully received the corresponding BonTech Security Alert.
